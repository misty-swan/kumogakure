# ADR-002: iOS タイマー計測・画面ロック許容・離脱検知方式

- **Status**: Accepted
- **Date**: 2026-11-20
- **Decision Makers**: オーナー / iOS リード

---

## Context（背景・課題）

企画書では「画面を離脱すると霧がリセットされる Forest 方式」と「最長 12 時間（明日の朝まで）」の両方が要件として挙げられている。
しかし iOS アプリにおいて、単純に `scenePhase == .background` をすべて「離脱＝リセット」と判定すると、**ユーザーがスマホの電源ボタンを押して画面をロックした瞬間や自動スリープした瞬間にもリセットされてしまい、2 時間や睡眠（明日の朝まで）のデトックスが成立しない**という致命的な問題が発生する。

---

## Decision（決定）

以下のハイブリッド方式を採用する。

1. **絶対時刻（`Date`）ベースのタイマー計測**
   - 1 秒ごとのデクリメントではなく、`startedAt: Date` と `plannedEndsAt: Date` を保持し、表示や霧進捗を `now` との差分で計算する。バックグラウンド停止・スリープ中でも時間は 1 秒も狂わない。
2. **`protectedDataWillBecomeUnavailable` による画面ロック判別**
   - `scenePhase == .inactive` 単体（通知センター・コントロールセンター一瞬表示・着信ダイアログ）ではリセットしない。
   - `.background` 遷移後、**1.5 秒以内**に `UIApplication.protectedDataWillBecomeUnavailableNotification` が発火した場合は「画面ロック（正当な放置）」と判定し、セッションを継続する。
3. **他アプリ遷移時の 10 秒猶予期間**
   - 上記通知が発火せずに `.background` となった場合（ホーム画面へ戻る、アプリスイッチャーで別アプリへ切替）は即リセットせず、**10 秒の猶予期間**（`gracePeriod`）を開始し、ローカル通知「霧が濃くなり始めています。10 秒以内に戻ると続けられます」を送信する。
   - 10 秒以内にアプリが `.active` へ戻れば継続、10 秒超過または未復帰のまま終了された場合は `interrupted`（霧リセット）として確定する。
4. **短時間集中向けの「画面オン維持」トグル**
   - 霧が晴れていく様子を眺めながら机に置きたいユーザー向けに、手動トグルで `UIApplication.shared.isIdleTimerDisabled = true` を選べるようにする（デフォルトは OFF で省電力）。
5. **シェアシート表示中の保護**
   - S-02 で `UIActivityViewController` を表示している間は状態機械を `preparingShare` 状態に保ち、離脱検知を起動しない。

---

## Consequences（結果・トレードオフ）

### メリット
- 「電源ロックして寝る」「机に置いて放置する」と「SNS や別アプリを開いてスマホを触ってしまう」を iOS 標準 API のみ（特別な Entitlement 申請なし）で実用上高精度に区別できる。
- Forest 等の実績ある集中アプリに近い直感的なユーザー体験を、誤爆ストレスを抑えつつ実現できる。

### 制約・既知の限界（Open / Phase 2 で解消）
- **パスコード未設定端末**: 端末にパスコード/Face ID が設定されていない場合、`protectedDataWillBecomeUnavailableNotification` が発火しない（データ保護が有効でない）ため、画面ロックも「10 秒猶予」対象となり離脱判定される可能性がある。画面内またはヘルプで「画面を点けたままトグル」の併用かパスコード利用を案内する。
- **ロック解除後の抜け道**: 画面ロック中に通知から直接別アプリを開いた場合、バックグラウンドにいる『雲隠れ』アプリ側からは即座に別アプリ起動を検知できない（次回『雲隠れ』に戻ったタイミングやアプリ強制終了では判別不可）。この完全な他アプリ制限は **Phase 2 の Screen Time API（`FamilyControls` / `ManagedSettings`）** で解決する。

---

## Alternatives Considered（検討した代替案）

1. **常時 `isIdleTimerDisabled = true` 強制**: 2〜12 時間の睡眠・長時間利用で画面焼けとバッテリー消耗が深刻になるため不採用。
2. **MVP からの Screen Time API 導入**: Apple への `com.apple.developer.family-controls` 特別利用申請・審査が別途数週間かかり、6 週間での MVP リリースに間に合わないリスクが高いため Phase 2 送りとした。
