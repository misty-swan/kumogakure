# ADR-003: セッション認可・ID 設計と OGP キャッシュ分離

- **Status**: Accepted
- **Date**: 2026-11-20
- **Decision Makers**: アーキテクト / Backend リード

---

## Context（背景・課題）

本アプリは「ログイン不要（匿名 UUID）」を前提としているため、通常の JWT セッション認証を持たない。その状態で以下の 3 つの課題に対処する必要があった。

1. **セッション操作権限の保護**: 企画書の初期案では `user_uuid` だけでセッション作成・終了を行う設計だったが、ログや共有先から万一 `user_uuid` が推測/漏洩したり、あるいはセッション ID（`a9x2k8` 等）だけで `/finish` を叩けると、第三者が他人の雲隠れを勝手にキャンセルできる。また 6 文字英数字では URL 総当たりリスクが相対的に高い。
2. **非公開セッションのプライバシー**: シェアせず「静かに始める」を選んだユーザーの入力や状態が `/s/{id}` から第三者に見えてはならない。
3. **OGP キャッシュ（24h）と状態更新の矛盾**: `/ogp/{id}.png` を Cloudflare で 24 時間キャッシュすると、ユーザーが 10 分で途中帰還しても SNS 上の画像キャッシュは変わらない。

---

## Decision（決定）

### 1. 10 文字 URL 安全 nanoid + `owner_token` 認証
- セッション `id` は 6 文字ではなく **10 文字 URL 安全 nanoid**（`[A-Za-z0-9_-]{10}`、約 60 bit エントロピー）を採用する。URL として十分短く（例: `https://kumogakure.app/s/k9x2m7p4q8`）、全数走査を事実上不可能にする。
- `POST /api/v1/sessions` 実行時に暗号論的乱数から **32 byte hex の `owner_token`** を発行し、レスポンスで 1 度だけ返却する。Turso には平文を保存せず **`owner_token_hash`（SHA-256 hex）** のみを保存する。
- `POST /api/v1/sessions/{id}/finish` は `Authorization: Bearer <owner_token>` を必須とし、SHA-256 ダイジェストの定数時間比較を行う。

### 2. `is_public` フラグによる公開範囲分離
- `is_public = 0`（シェアせず静かに始める）で登録されたセッションは、`GET /api/v1/stats/active` の同時人数カウントのみに含め、`/s/{id}` および `/ogp/{id}.png` では存在を秘匿し一律 `404 Not Found` を返す。

### 3. OGP 画像（不変）と Web ページ（準リアルタイム）の責務分離
- **`/ogp/{id}.png`（出発宣言カード）**: `Cache-Control: public, max-age=86400, s-maxage=86400, immutable` とし、SNS クローラー集中からオリジンと Turso を完全に守る。画像内容は「ただいま、雲隠れ中・帰還予定時刻」として一貫させる（そもそも X や LINE のクローラー自体が OG 画像を数日単位でキャッシュするため、動的変更を前提にしない方が UX の齟齬がない）。
- **`/s/{id}`（現在の状態）**: `Cache-Control: public, max-age=30, s-maxage=30` の短時間キャッシュとし、URL をタップしてブラウザで開いた相手には常に最大 30 秒遅れで「雲隠れ中 / 帰還済み / 途中帰還 / 24時間失効（410 Gone）」の正確な状態を提示する。

---

## Consequences（結果・トレードオフ）

### メリット
- OAuth/ログイン画面を一切増やさずに、他者による `/finish` 改ざん・ID 列挙・非公開セッション閲覧を防げる。
- OGP 生成コストがセッションあたり実質初回 1 回に抑えられ、Cloud Run と Turso の無料枠を極めて長く維持できる。

### 注意点
- iOS アプリが `owner_token` を紛失（アンインストール等）すると当該セッションを `/finish` できなくなるが、24 時間（`expires_at`）および `ends_at` 経過で自動的に同時人数カウントから外れるため実害はない。
- iOS アプリ上ではセッション完了まで `owner_token` を SwiftData（または一時メモリ＋再送キュー）に保持し、送信完了後に破棄する設計とする。
